# SEO

The canonical domain is `https://sayfit.ir/`.

## Sources

- Home metadata: `index.html`
- Persian home source: `index.html` and `i18n/fa.json`, generated by `tools/generate_persian_home.py`
- English and Persian project/category metadata: generated under `work/` and `fa/work/`
- URL inventory: `sitemap.xml`
- Crawl rules: `robots.txt`
- Redirects and headers: `.htaccess`
- Structured data: JSON-LD in home and generated pages

After changing project names, descriptions, categories or media, run:

```text
python tools/generate_project_pages.py
```

This generator also runs `tools/generate_persian_home.py`, which creates `fa/index.html` from `index.html` and `i18n/fa.json`. Do not edit generated files under `work/`, `fa/work/`, `fa/index.html`, or `sitemap.xml` by hand.

## Language URL contract

- English home: `/`
- Persian home: `/fa/`
- English Work: `/work/{category}/{slug}/`
- Persian Work: `/fa/work/{category}/{slug}/`

The URL path controls the language. English is always the default; browser language, local storage, IP, `Accept-Language`, and previous preference never automatically activate Persian. Persian is entered only by explicit user selection or a direct `/fa/...` URL. The language switch is a crawlable link and uses the History API to keep the current-page switch instant without reloading.

An explicit language selection creates a browser history entry. Back and Forward derive the language from the URL path and update the DOM without adding another entry. The current page remains mounted where practical, preserving scroll and Cube/carousel/project state.

Each language page self-canonicalizes. Matching English and Persian pages have reciprocal `en` and `fa` alternates; `x-default` points to English. Project slugs remain Latin and unchanged.

`/fa/...` pages are generated static Persian HTML, not English documents translated only after JavaScript runs. Direct visits and refreshes return Persian raw HTML with `lang="fa"`, `dir="rtl"`, Persian visible content and metadata where available, Persian structured-data values, and a Persian self-canonical.

Legacy `?lang=fa` and `?lang=en` are retired language URL forms, but their server-side migration is **not implemented in the website workspace**. Until the separate Server Work installs redirects, the path remains authoritative: `/fa/...` is Persian and every other path is English; `lang=` query parameters do not override the path. Do not add JavaScript redirects or simulate production routing in `.htaccess`. Server Work must install permanent redirects in the confirmed active Caddy configuration after transferring the prepared website files. See [Deployment](DEPLOYMENT.md#server-work-handoff).

The generated sitemap contains a `<url>` entry for each language URL. Verify every sitemap location and alternate target returns 200 locally after generation.

The current sitemap contains 22 English URLs and 22 Persian URLs (44 total). Sitemap locations, canonicals, and hreflang targets use clean path URLs only; none use `?lang=`. Each pair links reciprocally with `en` and `fa`; `x-default` points to the English URL.
